## 3. 结构重建 GPU hang 修复（已完成）

### 3.1 问题
N3F 训练在 step 101000（%1000 结构重建边界）GPU 100% 卡死。

### 3.2 根因
`csr_rebuild_kernel`（[coactivation_kernels.cu](file:///f:/thetrueai/src/snn/coactivation_kernels.cu)）只重排
`d_synapses` + `d_row_ptr`，**未同步重排 d_csr_col_idx 等 12 个 10.7M 对齐数组**
（col_idx / weights_cache / eligibility / eligibility_slow / alpha / beta / ca_snapshot /
x_pre_trace / trace_epoch / oxytocin_receptor / synapse_delay / camkii_activity）。
STDP/NMDA kernel 按突触索引直读 `d_csr_col_idx[post]` → 重建后 col_idx 与 d_synapses 错位 →
`spike_flags[post]` 越界 → GPU hang。此为所有模式共有的重建 bug（BPTT 跳过、纯 STDP 靠 `--no-structural-rebuild` 规避）。

### 3.3 修复
- 新增 `AlignedSynapseArrays` 结构 + `remap_aligned_arrays_kernel`（多 block 并行重排，目标只前移故无竞争）
- `zero_aligned_tail_kernel`：尾部 `[新总数, 10.7M)` 清零（防垃圾 post 越界）
- `launch_csr_rebuild` 内部 Step 7.5 调用（CSR 重建后、临时缓冲释放前）
- [scheduler.cu](file:///f:/thetrueai/src/snn/scheduler.cu) 调用处传入全部对齐指针；**N3F 保留结构重建**（仅 BPTT 因 V/S history 索引依赖继续跳过）

### 6.2 ⚠ 卡死：12000 步结构重建 GPU hang（已修复，2026-08-01）

- **现象**：12000 步（%1000 重建边界）`[Affective]` 已打印，重建日志未出现 → 卡在结构重建 kernel
- **根因**：`remap_aligned_arrays_kernel`（[coactivation_kernels.cu](file:///f:/thetrueai/src/snn/coactivation_kernels.cu)）多 block 并行搬运存在**跨 block 读写竞争**：
  - 线程 A（源 s=100，目标 t=90）写 `col_idx[90]`；线程 B（源 s=90，目标 t=85）读 `col_idx[90]` 作为源
  - 跨 block 无全局同步 → B 读到 A 写的新值 → col_idx 错位 → STDP/NMDA post 越界 → hang
  - 原注释"target <= source 故安全"论证有误（target 可等于其他线程的 source）
- **修复**：改为与 `csr_rebuild_kernel` 相同的**单 block + 双 `__syncthreads`** 迭代（每轮先读源 → sync → 写目标 → sync）
- **验证**：3000 步测试跨 3 个重建点，全部 `integrity=OK`，无 hang，速度无显著下降
- **临时规避（修复前）**：`--no-structural-rebuild`

### 6.4 二次死锁根因与修复：barrier 迭代次数不一致（2026-08-01 18:15）

- **现象**：§6.2 修复后重跑 20K，12000 步重建点再次 GPU 100% 卡死（日志停在 `[Affective] step=12000`，P3-D 重建 #12 未出现）
- **根因**：`csr_rebuild_kernel` 与 `remap_aligned_arrays_kernel` 的"单 block 双 `__syncthreads`"迭代存在 UB：
  - 原写法 `for (s = tid; s < n_old; s += bs)` 在 `n_old % bs != 0` 时线程迭代次数差 1
  - 例：n_old=9644615，bs=1024 → 余 583 → 前 583 个线程多迭代 1 轮，其余已退出循环
  - 最后一轮仅部分线程执行 `__syncthreads()`，其余线程已到循环外的 barrier → **barrier 计数错位 → 死锁**
  - `__syncthreads` 在迭代次数不一致的循环内是未定义行为：碰巧通过（#6）或死锁（#12）取决于余数与调度
  - 早期 3000 步"验证"实际全部被 5% 阈值跳过（prune < 5% 不执行重建 kernel），掩盖了该 bug
- **修复**（[coactivation_kernels.cu](file:///f:/thetrueai/src/snn/coactivation_kernels.cu)）：
  - 两 kernel 的存活搬运循环改为**统一迭代次数** `n_iter = (n_old + bs - 1) / bs`
  - 越界线程（`s >= n_old`）空转只参与 `__syncthreads`，不读写 → 所有线程 barrier 次数一致
- **验证**：完整 20K 重跑（§6.3）跨过 12000 重建点，20/20 重建 `integrity=OK`，无 hang
- **教训**：`__syncthreads()` 所在循环必须保证 block 内所有线程执行相同次数；"碰巧通过"≠"正确"
